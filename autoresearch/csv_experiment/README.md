# CSV版の実行方法

このディレクトリは、karpathy/autoresearchの実験方式を炉のCSVに応用した追加実装です。元のGPTや学習コードは使用せず、scikit-learnの回帰モデルをCPUで学習します。元レポ全体の解説は[ワークスペースのREADME](../../README.md)を参照してください。

## すぐ実行する

このMacにはPython 3.12の仮想環境と依存関係を準備済みです。ターミナルで以下を実行します。

```bash
cd /Users/cls-lab/Git/NEDO_RSI/autoresearch/csv_experiment
.venv/bin/python run.py --description "baselineの再実行"
```

1回の学習とvalidation評価を行い、RMSE・MAE・現在値をそのまま5分先に使う単純予測のRMSEを表示します。小さいほど良い指標です。初期モデルは標準化＋Ridge回帰です。

`run.py`は1実験を実行するコマンドで、自動でモデルを書き換える機能はありません。AIによる改善方法は後述します。

## 新しい環境でのセットアップ

Python 3.12が必要です。このMacではCodex同梱のPython 3.12から仮想環境を作っています。移動先ではPython 3.12を用意し、`.venv`をコピーせず作り直してください。

```bash
cd autoresearch/csv_experiment
bash setup.sh
.venv/bin/python prepare.py
.venv/bin/python run.py --description "baseline"
```

`requirements.txt`は実際にインストールした依存関係をバージョン固定しています。`uv`・NVIDIA GPU・PyTorchはこの追加実験では使用しません。元レポのルートで`uv sync`を実行するとCUDA向けの別環境になります。

CSVのパスは`config.json`の場所を基準に解決します。既存の準備データを意図的に作り直す場合だけ、`.venv/bin/python prepare.py --force`を実行します。元CSVは変更しません。

## 何を学習するか

- 仮の目的変数：`炉内ガス温度平均`の5分後の値。
- 入力：温度・流量など18列の現在、1分前、5分前、10分前（72特徴量）。
- サンプリング：正確な毎分00秒の観測を使用。1分平均への集約や補間はしません。
- 学習：予測対象時刻が2020-08-22 00:00より前。
- validation：予測の起点が8月22日以降、予測対象時刻が8月27日より前。
- test：予測の起点が8月27日以降。モデル選択中は評価しません。
- 分割境界をまたいだ教師データを除外し、シャッフル分割を避けます。検証時点の過去の観測は入力に使います。

CSV末尾にあるアラーム、予備列、逆算値、SV/MV操作関連などは初期特徴量に採用していません。列の定義や確定タイミングが不明なためです。選んだセンサ値にも実際の取得遅延がある場合は、モデルを実運用へ使う前にラグを見直す必要があります。

## データ品質の扱い

元CSVは276,392行・121列、CP932です。時刻順に並んでおらず、重複日時が8,640行分あります。完全に同一の行は0件でした。同一日時で内容の異なる1,440時点・10,080行は、優先すべき行の定義が不明なため、該当する全行を除外しています。今回の競合は8月31日の毎分の観測に該当するため、8月31日は評価に入りません。

欠損を埋めず、過去10分から将来5分まで毎分の必要センサ値があり、`稼働中 == 1`の区間だけを採用します。これは連続稼働区間のオフライン評価です。停止やセンサ欠測を含む全運転状態での予測性能は評価していません。将来の稼働状態は評価対象の選別にのみ使い、モデルの入力には渡しません。

ゼロ値は空欄と区別し、値だけを理由に異常値として除外しません。単位は元CSVに明記されていないため、RMSE・MAEも元列の単位で示します。詳細な件数・期間・CSVのSHA-256・特徴名は`data/profile.json`に記録されます。

### Codexが読む範囲

このフォルダは、CodexなどのAIエージェントがコードと指示書を読んで研究を進める構成です。ただし、フォルダ全体が自動で会話へ読み込まれることを前提にはしていません。上の開始指示で、必要なファイルを明示的に読ませます。`program.md`は通常のMarkdownファイルであり、置くだけで自動実行されるものではありません。

| 対象 | Codexの扱い |
| --- | --- |
| README.md、program.md | 課題、作業手順、変更可能範囲を読む |
| config.json、prepare.py、run.py、train.py | データ定義、評価方法、改良対象のコードを読む |
| requirements.txt、setup.sh、test_prepare.py | 利用可能なライブラリ、環境準備、確認方法を読む |
| data/profile.json | 件数、列名、時系列分割、データの識別情報を読む |
| results/results.jsonl、必要なrun.log | 既存実験のスコアや失敗を確認する |
| 元CSV、train.npz、validation.npz | Pythonが数値処理する。データ全件をチャットへ展開する必要はない |
| data/test.npz | この改善ループでは読み込まない |
| .venv/、model.joblib | 環境・モデルとして使用する。ファイルの中身を文章として読む対象ではない |

Codexがソースを読むことと、Pythonの学習モデルがデータを読むことは別です。数値データはローカルのPythonで処理し、Codexにはコード・指標・必要な要約を返します。操作説明の参考：[Codexの指示ファイル](https://developers.openai.com/codex/guides/agents-md/)。

### 完了時に残るもの

5回分の実験記録、最良の`train.py`と対応する保存済みモデル、比較表付きレポート、validationの予測グラフを残します。改善しなければbaselineを最良として残します。グラフは全検証期間の概要と、事前に固定した冒頭24時間を示し、見栄えのよい区間だけを選ばないでください。グラフ作成はこれからCodexが行う作業で、`run.py`の既存の自動出力ではありません。

1実験の子プロセスには標準300秒の上限を設け、超過時は終了します。元レポの「学習時間を約5分使い切る」方式とは異なり、この追加実装は学習が終われば早く終了します。依存ライブラリの計算スレッド数は2に制限しています。

`program.md`が編集可能範囲と採否ルールを定義します。この規約はAIエージェントが守る運用上の制約であり、悪意ある学習コードのデータ参照をOSレベルで隔離するものではありません。

## 保存される結果

実験ごとに`results/<日時_ID>/`を作り、以下を保存します。

- `result.json`：指標、成功/失敗、説明、実行時間、コードとデータのハッシュ。
- `run.log`：ログとエラー。
- `model.joblib`：学習済みモデル（成功時）。入力はprofile.json記載の72特徴量と同じ並びです。
- `train.py`など：実験時のコード、設定、データ準備の記録。

一覧は`results/results.jsonl`へ追記します。`data/`、`results/`、`.venv/`はGit管理対象外です。実験処理はローカルファイルのみを読み、CSVを外部へ送信する処理はありません。

モデルを選び終えた後に、明示的に最終テストを1回行えます。このコマンドは現在のtrain.pyで学習区間だけを再学習してtestを評価します。

```bash
.venv/bin/python run.py --split test --description "選択済みモデルの最終評価"
```

test結果を見てモデルを調整すると、独立した最終評価として使えなくなります。目的変数や予測時間を変更する場合は`config.json`を編集してデータを作り直し、新しい実験として比較を始めます。

## 確認コマンド

```bash
.venv/bin/python -m unittest -v test_prepare.py
.venv/bin/python -m pip check
```

テストは予測時間、過去ラグ、分割境界、重複日時、欠測区間、未来の値を変えても過去の特徴量が変わらないことを確認します。
